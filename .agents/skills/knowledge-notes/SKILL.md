# 本项目技术笔记

## 定位和写法

- 面向初学者，从使用场景和基本概念出发，逐步深入流程、关键实现、使用方法和易错点；已有主题先读对应笔记及导航，避免重复或断章。
- 每段只讲一个重点。用短句、清晰标题、必要的表格、示例和图解释；删除套话、对话痕迹及与学习无关的背景。内容要足以解释因果，不能为了精简省略必要步骤。
- 优先绘制结构图、调用链或时序图。让参与者、进程或线程边界、箭头方向、调用顺序、条件分支和返回路径符合真实实现；注明简化和版本差异。不要用装饰性插图代替机制图。
- 代码示例可直接理解或使用，包含必要上下文和关键注释。真实源码片段标明类、方法、版本和直达来源；删节处明确标注，不将示意代码冒充原文。

## 准确性和证据

- 先查用户提供的材料，再以权威一手资料核实具体实现：例如 AOSP 固定版本源码、官方文档、协议标准或库的官方源码。核对跨类调用顺序、默认值、条件和版本适用范围。
- 严禁猜测 API、版本、数据、参数、源码行为或来源。证据不足时继续查证；无法确认则明确说明缺口，不把推测写成事实。若参考链接无法访问，说明限制，不声称已读或已参考正文。
- 区分调用关系与依赖关系、跨进程与进程内调用、注册与就绪、客户端代理与服务端对象。安全、并发等敏感结论要交代适用条件和边界。
- 不虚构专家、审核人员或审核通过结论。只有实际执行独立评审且具备证据时，才如实描述评审范围和结果。

## 实施与验收

- 阅读仓库导航、已有格式和相关规则；新主题放进适当分类，更新导航及受影响的链接和必要测试，保留用户已有改动。
- 检查每张图的文字、箭头、顺序、条件和与源码的一致性；检查代码片段、来源链接、标题目录的对应关系。
- 运行与变更相关的项目测试、构建和 `git diff --check`。在实际浏览器检查桌面与手机宽度，包括文字裁切、图表渲染与缩放、代码和表格滚动、导航和搜索。不能完成某项时说明原因及未验证范围，不将构建成功等同于视觉或内容验收通过。
- 遵守用户和仓库的修改、提交与发布授权；技能本身不授予发布权限。报告具体改动、已验证证据和未解决限制。
