# Android 安全知识库验收方案

## 目标、基线与证据

将原提纲转成可分组、分级阅读的专业文章；纠正旧结论，而不是按标题扩写。[原文覆盖基线](./android-security-source.md)的 S 编号是唯一原文标识，产品规划决定文章拆分和学习层级，`docs/.vitepress/navigation.ts` 的 `knowledgeSections` 决定实际导航。本文不另维护文章总数或分类副本。

本文件是待执行的验收计划，不代表内容已审校、示例已编译或设备已验证。实施记录须区分源码核对、示例编译、隔离运行、浏览器交互、截图视觉、物理触控和线上检查；记录文件版本、环境、步骤、结果和限制，不将构建通过写成全部验收通过。

## 内容完整性与分级

- **SEC-QA-01，P0：原文闭环。** 从源文件提取全部 S 编号，与覆盖账本做集合比较；每段必须指向最终文章路径及小节，注明保留、合并、纠正或历史适用。标题段允许映射到分组导读，但具体风险必须落到实质正文；同一内容可合并，不要求一段一篇。不得靠空白占位、待补充或静默删除满足“全部转换”。
- 账本至少包含 `S编号 / 原表述 / 文章与锚点 / 处理方式 / 核对来源 / 版本条件 / 验证状态`。无法证实的旧断言须说明证据不足及可确认的边界，不包装为已证实漏洞。
- **SEC-QA-02，P1：学习路径。** 对照产品定义逐级检查前置知识、适用读者和关联阅读；分组导读说明先学什么，文章明确风险成立条件、机制、错误模式、防护、验证路线和局限。避免将简单 API 罗列当作专业解释，也不机械要求每篇相同章节或图表数量。

## 原文专项纠错清单

以下是必须重新查证的审题点，并非对原断言的认可；任一强断言缺少条件或证据，按 SEC-QA-03 阻断。

| 原文范围 | 必查问题 |
| --- | --- |
| S3–S21：Activity、导出、Intent、链接和输入 | 区分安装要求、默认值和运行时权限；核对 OS 与 target SDK 条件。`setPackage`、显式组件、Intent URI、外部 extras 和转发不是同一安全边界；键盘配置不能被表述为全面防键盘记录。 |
| S24–S36：广播 | 分开动态/静态接收器、注册 flags、系统广播例外、权限与发送方校验，核对不同版本要求；解释广播嗅探和 sticky 风险的成立条件，不能把 action 字符串当授权。 |
| S39–S54：Service、AIDL、Messenger、前台服务 | 区分绑定入口和业务 Binder 方法鉴权、调用 UID 与异步身份丢失、并发及本地直接调用；Messenger 不自动提供权限。前台服务受版本、类型、权限和启动来源条件约束，不是保活保证。 |
| S57–S96：Provider、URI、FileProvider | `getType()` 的访问行为及匿名 MIME 路径须按版本核对，禁止照抄“无论是否导出或有权限均可调用”；authority 冲突与抢占须限定安装、包和用户条件。URI path 权限、临时授权、路径遍历、SQL 参数化分别解释；FileProvider 目录最小化不能变成一概禁用 files-path/cache-path。 |
| S99–S159：配置、身份、数据与动态加载 | 核对 sharedUserId 的历史与迁移限制、signatureOrSystem 的适用性，避免推荐过时等级；allowBackup、debuggable、taskAffinity/launchMode 分开讨论，备份须区分云备份和设备迁移。权限、元数据、包内文件、卸载残留、剪贴板、混淆、模拟位置和动态加载均限定威胁模型，不能凭目录名、开关或混淆断言安全。 |
| S162–S174：文件、传输、图片 | 上传/下载区分来源、授权、存储落点与资源限制；路径拼接和文件类型检查不能只依赖后缀。Bitmap 示例考虑采样、尺寸/内存预算及异常边界，不把捕获所有错误当防护。 |
| S177–S240：特殊 API 与可用性 | 命令执行、解压、反序列化、表达式注入与 DoS 必须给输入可控性和实际危险执行点；TA 先定义对象与执行环境。Base64/URL 解码、URI 分段和查询解析本身不是漏洞，核对解码顺序、编码、边界及错误处理。PreferenceActivity/Fragment 注入注明历史版本；EditText 场景补足索引与长度条件。 |

额外逐条核查以下容易被原文措辞掩盖的错误：

- S72、S201、S213–S225：URI grant 不是简单的“禁止隐式 Intent”或“flag 恰好等于某常量”；检查位组合、`setFlags`/`addFlags`、data/ClipData、目标选择、读写范围和授权生命周期。
- S117、S120、S144、S156：禁止无依据保留“所有私有组件不能设 taskAffinity/launchMode”“指定包目录不得含某扩展名”“检测开发者选项即可可信判断模拟位置”等结论；安全结论必须说明攻击条件与防护能力上限。
- S237：Binder 共享事务缓冲区不能直接写成单笔固定硬上限；核对返回数据、并发与异常传播。`getPackageInfo(..., 0)` 的返回内容和非零 flags 各自含义须查 API，不得写成“0 只有版本、其余都必须 try/catch”。
- S192、S195：对照[资料核对](./android-security-research.md)检查 JEXL 的确切版本、权限/特性默认值与显式配置，不用旧版行为推断新版默认可执行任意操作。原文 TA 只有标题，若按 Trusted Application 展开，须明示解释前提，不将 Trusty 等同全部 TEE，也不虚构具体漏洞。
- 拼写错误可修正，但保留 S 编号对应关系，例如 ContentProvider、PreferenceActivity、getPackageInfo、protectionLevel；不能把原文拼写当作真实 API。

## 技术准确性、版本与来源门禁

- **SEC-QA-03，P0：强断言审校。** 全文搜索“一定、所有、必须、禁止、无法、永远、仅、最大”等词，逐条核对上下文和证据。区分规范要求、平台实现、配置建议与团队策略；防护措施不得承诺消除未覆盖的攻击面。
- **SEC-QA-04，P0：版本可追溯。** Framework 源码使用已核实的固定标签；AndroidX 等独立项目使用各自准确版本或提交，不能套用平台标签。版本条件同时记录运行 OS、target SDK、必要的编译 SDK/依赖和安装或迁移场景；当前行为不能倒推旧版本。对关键分界给官方依据，尚未证实的精确切点不写。
- **SEC-QA-05，P0：来源覆盖。** 每项核心机制、漏洞成立条件、防护限制和版本变化均有可定位的官方 API、Android/AOSP 文档或固定源码链接。对照实际函数体及调用方，不仅引用注释或文件首页；CVE/安全公告核对影响范围与修复版本，缺证据不编造编号。原提纲只作为主题线索，不作为技术事实的唯一证据。
- 检查链接是否支持紧邻的具体结论，区分源码可确认与作者推论；可访问不等于内容支持。正文、表格、示例和 Mermaid 采用一致术语与条件，禁止图中跨过权限检查、线程切换或版本例外而正文另作补救。

## 示例安全与验证诚实性

- **SEC-QA-06，P0：示例不误用。** 明确完整可运行示例、教学片段、伪代码和反例；反例标记危险点，不作为推荐配置。公开 SDK 示例核对签名、参数、Manifest 与资源关系；不猜版本、工具包、flags 或隐藏 API 可用性，不把 `catch Exception`、关安全开关、扩大共享目录当通用修复。
- 示例只使用自有隔离数据和最小权限。演示命令、解压及文件处理须限定测试目录、输入和资源预算；不得夹带真实密钥、用户数据、生产域名或针对第三方的操作步骤。对输入做严格限制，但不要用“过滤几个字符”替代安全执行或规范化后的边界判断。
- **SEC-QA-07，P0：验证状态真实。** 未编译就标教学片段/未编译，未运行就标待验证路线；不能写“已复现”“测试通过”“适用全部设备”。若开展设备实验，先实际查询设备版本与配置，保存前置条件、预期和观察结果。缺设备不阻断有来源且标注清楚的原理文章，但不能声称完成设备验收。
- 对完整可运行的新增示例执行有意义的编译或隔离验证；仅在解释依赖实际结果时增加相应实验。测试风险路径和边界条件，不为复制示例文字或现有组件标记创建琐碎单元测试。

## 站点与移动端端到端验收

- **SEC-QA-08，P1：入口与检索。** 从生产构建的安全分类页、桌面左侧栏和手机目录到达每篇文章；分组/学习层级与配置一致，高亮和折叠正确，无重复入口或遗漏。每篇选一个仅出现在正文的中文短语验证搜索及锚点，另查混排 API 名、无结果、键盘选择和手机点击；不得只测试标题命中。
- **SEC-QA-09，P1：阅读与图示。** 桌面及 320、390、768 CSS 像素视口检查长 API、代码、表格、注释与图；无整页横滚，局部滚动可操作。截图检查字号、行距、层级、对比和密度，200% 浏览器缩放后仍可读；真实视口尺寸写入记录，不能只写设备预设名称。
- 有必要的图示才增加 Mermaid；逐图检查含义、有效 SVG、内部导航和明暗切换。对本批图示执行放大/缩小、复位、拖动、关闭/ESC、焦点恢复、滚动恢复及全屏拒绝回退。沿用 [全站 QA 方案](./QA.md) 的图片、错误图降级及可访问性检查；实际多点触控不可用时将 pinch 明确记为未验证，不能因此宣称完整手机验收。
- 原文没有图片附件，不虚构已取得的原图。新增图片核对来源、alt、MD/HTML 放大和失效降级；异常媒体夹具留在隔离缓存目录，不进入公开文章导航。

## 构建、链接与放行

- **SEC-QA-10，P0：产物完整。** 依次执行 `npm run test`、`npm run docs:build` 和 `git diff --check`；使用 `npm run docs:preview` 检查实际产物。所有新增路由、导航、正文锚点、本地资源和搜索资源有效，独立 `.html` 深链直接打开及刷新成功；无新控制台错误或必需资源失败。
- 现有构建门禁继续检查旧站复制哈希和产物排除项，不修改过期域名配置、不泄漏 `planning/` 或作者源码。按 `knowledgeSections` 派生实际文章与路径集合，不在多个报告里手工复制页面总数；外链单独核对内容、固定版本和可达性，区分网络暂时失败与失效链接。
- 发布、提交和推送不属于本计划的执行授权。线上 Pages URL 检查仅在后续获得发布授权后执行；本地预览结果不能替代线上检查。
- 评审输出使用稳定问题编号、P0/P1、文件行号、事实依据与具体修订建议。按多角色流程修订并二轮逐项关闭问题后进入写作/实施；最终内容审校无剩余 P0/P1，覆盖账本闭环，构建门禁通过且浏览器关键路径实际完成，才可记为本批本地验收通过。设备、触控、截图或线上限制单独列明，不省略也不虚报完成。
