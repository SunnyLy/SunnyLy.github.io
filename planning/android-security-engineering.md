## 原文专项修正

以下细节在主文章中解释，依据见 [资料核对](android-security-research.md)，不以旧笔记作为事实依据。

- 权限：普通应用权限与平台特权不同；`signatureOrSystem` 已弃用，不是一律推荐；组件导出、签名身份、账户级业务授权分别校验。
- Activity：任务栈属性按功能和系统版本评估；显式 Intent、`setPackage`、域名验证均不能替代业务授权。不能仅靠导出回调推断真正调用者。
- 广播与 IPC：动态广播导出有 OS/target 和系统广播例外；Binder 调用身份在具体事务中取得，异步切线程前留存已验证身份；AIDL/Messenger 不自动提供业务鉴权。
- Provider：MIME 查询与数据读取不同，解释 API 34 的 `getTypeAnonymous`；authority 冲突、名称抢先占用与任意劫持不是同义词；路径权限和临时 URI 授权分别处理。
- FileProvider：允许专用窄范围 files/cache 子目录；禁止过宽共享、非预期可写授权与未检查的路径，不能把所有内部目录元素整体禁用。
- 发布与数据：`debuggable` 与备份策略分开；备份/设备迁移、退出/卸载、设备绑定/账户授权分别说明，不能假设客户端数据携带即可授权。
- 文件：上传与下载同时校验来源、路径、大小和服务端授权；图片解码限制像素及内存预算，解压限制落点与展开资源，考虑可信目录假设和竞态。
- 注入与解析：命令参数化仍需防参数注入；JEXL 默认值随版本变化；反序列化不能靠类型名保证安全；Base64 不是加密；URI 解码不能重复或混用表单语义。
- 可用性：Binder 文档所述当前共享缓冲预算不等于单次独享上限；`getPackageInfo` 的 flags 影响附加字段，非零与异常没有必然对应关系，不能笼统 catch 所有 RuntimeException。
- UI 与位置：`setSelection` 应对实际文本长度检查，maxLength 不是必要条件；历史 Fragment 注入明确适用对象；开发者选项与位置真实性不能画等号。
- TA：原文仅标题，条件解释 Trusted Application，限定平台/OEM/TEE 领域；Trusty 不是全部 Android 设备的唯一 TEE，不声称普通 APK 能任意加载 TA。
