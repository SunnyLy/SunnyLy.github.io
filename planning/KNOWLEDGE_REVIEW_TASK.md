# 知识库专业性与正确性复核任务

## 用户目标与授权

用户要求开启后台任务，对本次整理的全部知识点进行专业、严谨的 Review，发现错误直接修改。应完成实质审阅与必要修订，不只检查链接或生成审阅计划。当前用户允许直接修正，但禁止 git commit、push、tag、破坏性清理及擅自发布。

## 范围与优先级

1. 优先审阅 `docs/android/basics/` 全部文章与索引。重点是 `system-services.md` 的 AMS/ATMS 完整启动时序：从 Launcher 点击图标到应用首帧，包括身份、任务解析、进程复用、AMS/Zygote/USAP、attach 分支、主线程队列、Application/Provider、Activity 生命周期、窗口与显示合成。区分源码事实、逻辑阶段图、并发关系和实际显示完成。
2. 继续审阅 `docs/android/framework/`、`docs/android/kotlin/`、`docs/security/android/`、`docs/reverse/` 以及站内抓包实践笔记，核对本次会话整理的全部正文知识点。先由导航与文件清单确认实际路径，不猜测文件名。安全旧专题可保留兼容，但不可与当前五章结论矛盾。
3. 不审改旧博客生成文件、依赖包或第三方工具附件内容。不得新增用户明确排除的 Frida Hook、strace 专题；保留原提纲和分组，不能重新按自定义体系拆散。

## 复核标准

- 核对概念、职责、进程/线程、接口类型、调用顺序、缓存/生命周期、异步完成、失败与权限边界。完整阅读每篇正文，按段落或小节形成审阅记录，避免以关键词扫描替代审阅。
- 以 Android Developers、固定 AOSP 标签、Kotlin/AndroidX 官方文档与源码、浏览器规范等第一手资料核验。Android 内部实现优先沿文章已声明的 `android-16.0.0_r1` 复核；其他版本需单独标明。不要将较新或不同版本实现直接替换为同一版本结论。
- API 名称、签名、参数、返回类型、API level、target SDK 条件、标志位组合及示例异常处理都要实际查证。不要从目录名推断设备或系统版本。未经编译和设备执行的示例必须如实标注。
- 区分原提纲错误与补充结论，引用贴近具体论断。无法核实的内容应明确限定或移除无依据的断言，不得凭印象补齐。
- 对每个问题记录文件/小节、原错误、正确结论、第一手来源和修改结果；对已审阅且无问题的文章也记录覆盖状态。不得将“构建通过”当作内容正确的证明。
